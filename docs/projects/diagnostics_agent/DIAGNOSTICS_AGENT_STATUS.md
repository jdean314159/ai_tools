# diagnostics_agent — Status & Handoff

**Purpose:** read-only local-LLM system diagnostics tool in the `ai_tools` monorepo.
**Pipeline:** collect → triage (deterministic) → interpret (local LLM) → audit.
**Posture:** local-only, sandboxed, propose-not-execute, fail-loud, auditable.
**Tests:** 100 passed, 1 skipped (live-model E2E).

---

## Current state — built & working

- **Phase 0 — `sandbox.py`:** `ReadOnlySandbox`, `SandboxConfig`, `make_staging_sandbox()`. Rootless Podman, `--network none`, `--read-only`, `--cap-drop ALL`, keep-id userns, staged file 0600.
- **Phase 1 — `triage.py` + `rules.py`:** severity from journald `PRIORITY` (not keyword guessing), template-masking clustering, findings-vs-clusters split, conservation invariant. Self-noise exclusion matches **structured** `container_name.startswith("diag-sbx-")` with `excluded_self_noise` counted into conservation.
- **Phase 2 — `interpret.py`:** `LogInterpreter`, two-axis `security_risk`/`operational_risk`, `ConcernAssessment` field order `finding_ref → rationale → severity` (reason before label), local-only guard (backend-name allowlist), `json_schema` + retry-once. Calibration guidance in prompt (auth weighted by service + frequency). **Deterministic operational floor** (disk/memory/stability ERROR→≥medium, CRITICAL→≥high; auth NOT floored; matching concerns clamped).
- **Phase C — `orchestrate.py` + `collect.py`:** `DiagnosticsOrchestrator`, `DiagnosticResult`, `Collector`/`CommandCollector`/`journalctl_collector`. Partial-failure tolerant; fail-loud on sandbox read error/timeout.
- **UI — `ui/app.py` + `models.py`:** Streamlit. Ollama model picker, VRAM-fit annotation (`detect_hardware().vram_free_mb`), run-on-button-only, render-from-state, partial-result rendering.

## Open items — priority order

1. **Truncation fix (TOP, actionable now).** `max_output_bytes` default 1 MiB clipped a 2.4 MB collection on the laptop → triage saw ~40%. Worse: `journalctl` is oldest-first, so truncation drops the **newest** entries (keeps boot burst, loses recent runtime). Three-part fix:
   - **Field projection in `journalctl_collector`:** add `--output-fields=PRIORITY,MESSAGE,SYSLOG_IDENTIFIER,_COMM,CONTAINER_NAME,_SYSTEMD_UNIT,USER_UNIT` (audit the full set the triage/rules/self-noise actually read; add a test asserting the collector requests every consumed field). ~5–10× line-size cut — the biggest win, attacks the cause.
   - Raise `max_output_bytes` to 8–16 MiB (backstop).
   - Surface truncation as a **visible warning**, not just a metadata flag.
2. **Follow-up Q&A — build it.** Spec delivered (`FOLLOWUP_QA_BUILD_SPEC.md`). `FollowupChat`, grounded read-only over `DiagnosticResult`, reuse engine + **shared** local-only guard (extract guard so `LogInterpreter` and `FollowupChat` share one impl), free-text (no schema), capped history. Bright line: cannot fetch/run/mutate — that's Phase 3.
3. **`overall_risk ≥ max(concern severity)` clamp.** Deterministic consistency; a medium concern under a low/none overall is incoherent (seen on the laptop NVIDIA run). Cheap.
4. **Ground system facts in the interpreter prompt.** Feed real `uname -r`, distro, hostname (pulled deterministically) so the model can't fabricate them (Phi-3 invented "Ubuntu 20.04 / 5.13"). Closes one confabulation category.
5. **`service_failed` rule false-positive.** Check-and-exit daemons exit non-zero cleanly (snap.prompting-client: `status=8`, `inactive (dead)`, NOT `failed`). Weight the rule by actual `failed`/restart-looping state — systemd distinguishes `failed` from `inactive (dead)`; only the former is usually worth surfacing.
6. **`*.egg-info/` → `.gitignore`** (reappeared in tarball; regenerated by editable install).
7. **IP-mask regex** catches dotted version strings (`1.6.99.901` → `<IP>`). Cosmetic; tighten to octets ≤255 if it bothers.

### Future (not now)
- **Structured baseline/trend store + disposition memory.** Change-detection ("is ata10 new/worsening, or constant since boot?") + confirmed-benign override — the only legit way to demote a floored-but-benign recurring signal (the deterministic floor now pins ata10 at medium forever). Deterministic store fits trend better than engram; engram fits fuzzy disposition but inherits contradiction-bleed.
- **Phase 3 — generated-query exploration (gated).** Decided design: a **vetted parameterized check catalog (allowlist)** the model selects from — NOT free code generation. The catalog also grounds `recommended_checks` now and serves as a human runbook. Structured YAML, single source of truth, version-controlled, strict parameter validation (argv not shell), privilege flags. **Starter catalog still to draft** (agreed in principle, superseded by other topics). KEV/CISA rejected as layer mismatch — CVEs-in-products vs system logs, and KEV barely overlaps a Linux workstation; a vuln-scan module with KEV as a priority overlay would be a *separate* capability.

## Locked decisions (don't relitigate)

- **Push non-negotiable judgments into the deterministic layer; treat LLM output as commentary to verify, not fact to trust.** Validated repeatedly — every confabulation this project hit was in the LLM narrative; the deterministic triage stayed honest.
- **Two risk axes** (security vs operational) — a single axis gets pulled toward whichever framing dominates the prompt.
- **Deterministic floor for hardware presence; LLM judgment for auth context.** Hardware = "presence implies concern" (floor it); auth = "context implies concern" (don't floor; judge by service + frequency).
- **Calibration is probabilistic on local models — spot-check across models.** Field-order bug surfaced only by running a second model; small models confabulate (see below).

## Laptop / model findings (4 GB GTX 1650)

- **4B models OOM** on 4 GB (compositor takes a share; 4B Q4 ≈ 2.5–3 GB weights + KV cache tips over).
- **3B-class models confabulate on this task** — Phi-3-mini invented OS/kernel; llama3.2:3b invented finding IDs (`DEP-1234`/`SEC-5678`) and security framings on benign boilerplate. **Capability floor for grounded interpretation is above what fits fully on 4 GB.** A confabulating interpretation is worse than none.
- **Decision: laptop = deterministic collector.** Collection + triage need no GPU and are trustworthy. For interpretation, either (a) point the laptop's `OllamaEngine` at the workstation's LAN IP (passes the guard — it keys on backend *name*; it's your own trusted box, not cloud), or (b) run deterministic-only and read the triage summary directly. The llama.cpp partial-offload path (`-ngl` + `--cache-type-k/v q4_0` + `--flash-attn`) is worth ONE experiment, expect slow, and it must pass the grounding test regardless.
- **Grounding test** (now that there's ground truth): run a model, check whether it invents system facts you can refute with `uname -r` / `lsb_release -a` (laptop: Ubuntu 25.10, kernel 6.17.0-23-generic). Inventing them = disqualified for the interpretation layer.

## Forward architecture — the "computer helper"

- **Suite of bounded capabilities on a shared substrate — NOT a monolithic agent.** Build capabilities the way diagnostics was built; let an orchestrating/routing agent emerge last, once pieces are solid and you've felt the friction of switching by hand.
- **diagnostics_agent is ~60% substrate already.** Reusable: `sandbox`, `models` (discovery), `Collector`/`CommandCollector` base, a `StructuredInterpreter` core (engine + local-only guard + schema + retry), the orchestration/result+audit contract, the UI shell, the check catalog. Capability-specific: `triage`, `rules`, the `Interpretation` schema/prompt, `journalctl_collector`, the diagnostics UI page.
- **Factor a shared package (e.g. `ai_helper_core`) when the 2nd capability appears** — co-evolution, not up-front abstraction.
- **Candidate capabilities:** file organization (write-risk → propose/confirm/execute + backup boundary; reuses the catalog as a vetted file-ops allowlist) and photo-description matching (multimodal retrieval via `rag_lib` + image embedder; thin LLM). Order by which you'd actually use more.

## Launch reference

Per machine (recreate venv — venvs are NOT portable; copying breaks the shebang/symlinks):
```bash
rm -rf ~/ai_tools/.venv
python3 -m venv ~/ai_tools/.venv
source ~/ai_tools/.venv/bin/activate
pip install --upgrade pip
cd ~/ai_tools/llm_harness_core && pip install -e .
cd ~/ai_tools/llm_engines      && pip install -e .
cd ~/ai_tools/examples/diagnostics_agent && pip install -e ".[ui]"
```
Run:
```bash
cd ~/ai_tools/examples/diagnostics_agent
source ~/ai_tools/.venv/bin/activate
streamlit run src/diagnostics_agent/ui/app.py      # http://localhost:8501
```
Requires `systemd-journal` group membership (NOT root) and rootless Podman with the fuse-overlayfs `storage.conf` + `podman pull docker.io/library/alpine:3.20`. A `setup.sh` running the three editable installs would make a fresh machine a one-liner.
