---
description: Software Architect review ritual for sprint-ready features
argument-hint: [sprint-number]
---

Use this when acting as the SoftwareArchitect reviewing Sprint $ARGUMENTS deliverables:

1. State that developer tasks are ready for review, then check mail and your todo log so architectural concerns are up to date.
2. Review each implementation thoroughly (design trade-offs, edge cases, adherence to ADRs). Run tests in small batches as you validate specific components.
3. Once the review is complete, notify the team with findings, approvals/blockers, and any follow-up work—CC ProjectManager, ProductManager, BackendDeveloper, TestsDeveloper, ProjectReviewer, and DocumentationWriter so downstream owners know architecture is ready.
